What the build is actually for

Three failures a platform is judged on.

A data platform earns trust in one place: a number on a screen traces back to the rows it came from, without anyone asking.

The same thing, twice

One patient, or one product, arriving as two records because nothing resolved identity at the door. Everything downstream inherits the duplicate, and every report built on it disagrees with its neighbour.

Two definitions of one metric

A definition that quietly drifted from the one in the report upstairs. Layered modelling and tested transformations give analysts and models the same agreed definitions.

A pipeline that breaks on a Tuesday

A source changes shape and the run that fails is three stages downstream. Schema reconciliation at the entry turns that into a warning instead of an outage.

Sequence

Decided before the first table exists.

Identity comes first: what makes two rows the same person, the same medicine, the same contract. It is the spine of the platform, and it is written down rather than assumed.

Then the entry. Source systems, streams, files and clinical feeds land in a governed entry zone with lineage from the first byte.

Then the layer people actually query. Self-service analytics, BI and exploration sit on the governed semantic layer, not on exports.

Which table format and which orchestrator are choices you can defend afterwards. Those three are not.

Case studies

Proof of work in each area.

Pharm Platform

An open-data intelligence platform for pharmacy. A phased build takes ingestion of Eurostat, CTIS and ChEMBL through canonical drug identity to analytics-ready models, forecasting and a knowledge-graph decision gate — with no patient-level data anywhere in the pipeline.

View architecture

EHR ETL Pipeline

A deterministic mapping pre-pass and Dagster-orchestrated conversion turn non-compliant raw EHR (Electronic Health Record) extracts into governed FHIR R4 and OMOP CDM outputs. Each layer lands as an atomic DuckLake Parquet snapshot and advances independently, so a degraded run never discards healthy data.

The expensive part

What getting it wrong costs.

Never the storage bill. It is the quarter lost deciding which of two reports is right, and the audit question nobody can answer: who else has been able to read this table, and since when.

So the boring controls are the deliverable. Access policy, quality checks, privacy controls and audit trails run as code across every stage.
