What earns a model its place

A model is a decision with a baseline.

A model ships only against a decision someone makes, with a baseline to beat and a human review path when it is wrong.

That rule decides the architecture rather than the last phase of it. The evaluation harness is a component in the graph, not a report written afterwards, and the review path is a queue somebody owns.

It also decides what we decline to build. Where a deterministic map gives the same answer with no variance to defend, we build the map and leave the model out of the data path.

Assistants and automation

Grounded, or it is a rumour.

An assistant over your own documents is only useful when every claim can be pointed at something. So the retrieval layer is designed before the prompt is, and the answer carries its sources or does not arrive.

Whether the words come from a hosted model or one running on hardware you control is a deployment choice, not a design choice. We write the graph so either can answer, and so switching is a configuration change rather than a rebuild.

Context is a budget. What the agents have already learned is kept in one shared place and stays lean between runs, and a finished analysis is cached rather than paid for twice.
